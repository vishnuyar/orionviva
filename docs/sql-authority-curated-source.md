## Options and recommendation

**Decode any envelope with familiar acquisition metadata.** This is cheap, but known strings and a recomputed hash do not prove that a reading was issued by the pinned pack. It would weaken source provenance and trust a caller-controlled assertion. Reject it.

**Privately issue pinned-pack source admission and faithfully support the existing exact source-reference identity rule. Selected.** Source binding alone would leave every actual balance PDF blocked by the prototype's deliberate full-number limitation. Combine the source boundary with one explicitly reviewed identity extension already settled in the production resolver: eligible exact references without a usable numeric identity signal, with its existing precedence, compatibility and ambiguity behavior. This is the independently approved new fence, not permission inferred from the old slice. It reuses reviewed source and resolver helpers, preserves raw receipts, and makes a meaningful actual-source financial comparison possible without inventing rules. A fresh experimental format keeps the change reversible; production integrity equivalence is not claimed.

**Complete source binding first and leave identity to another brief.** This is reversible and can prove encrypted receipt/source machinery, but it knowingly leaves all 420 actual financial admissions blocked. A separate identity-only slice still needs the composed captured-page boundary to admit those references safely. Prefer the combined bounded vertical slice above. If review cannot prove faithful indexed resolver support, hold this brief rather than calling zero promoted documents a financial success.

**Adopt the old financial ingestion path or invent broader identity/correction rules.** Reusing the old projector would reintroduce history reconstruction. Labels alone, custom reference normalization, new scoring, inferred holder ownership, altered ambiguity precedence, overlap acceptance or correction/corroboration rules exceed this brief. Reject them. The only approved identity expansion is a faithful, independently fact-checked indexed adapter to the already settled exact source-reference rule; all genuine gaps remain visible.

If implementation or fresh verification cannot establish the composed membership/source boundary or preserve the unconditional raw-receipt contract, return that finding to design. Do not bypass a source check to make the sample pass.
