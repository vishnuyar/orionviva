# Prepared synthetic sample

**State:** implemented restore and packaging path; complete artifact and
installed delivery unverified. The current evidence and remaining gates are in
[the import performance plan](import-performance-plan.md). Existing installed
builds have not been replaced by this engineering run.

The implementation restores a separately packaged encrypted synthetic vault.
This restore path does not call a provider or rebuild all original documents on
the customer's machine. Missing, changed or incompatible artifacts fail
preparation; there is no automatic fallback to a long import. An existing sample is preserved
until its replacement passes all checks and the active pointer is atomically
replaced. Installed-host acceptance remains outstanding.

The original source closure remains `sample_data/five-year-life-v1`: exactly 794
PDFs plus its manifest, curated readings and closure receipt. The prepared
artifact destination is separately under `sample_snapshots/five-year-life-v1`,
containing `vault.zip` and `snapshot.json`. When built, the resource module pins
the metadata digest. The metadata records every member's length and digest,
and binds the artifact to the source
closure and a portable digest of package sources, prompts and financial schemas.
The packaging command rejects stale artifacts after source changes. Package
sources also ship in the frozen sidecar so this compatibility digest is portable
between the source builder and installed runtime.

Restoration creates fresh private owned files without links, rejects duplicate,
absolute and traversing archive names, and bounds streamed hashes and copied
bytes. It authenticates and opens the canonical encrypted event history, checks
exact original-document equality and capture closure, reruns financial source
completion checks, and validates the SQL projection. Runtime-bound readiness
receipts are generated by the restoring runtime. Only then can activation publish
the new instance. The synthetic passphrase is public; personal vaults always use
their own credentials.

To rebuild after package changes, finish the candidate source first, then run:

```sh
PYTHONPATH=product:core:merchant .venv/bin/python scripts/build_sample_snapshot.py \
  --base /private/tmp/orionviva-synthetic-build \
  --output product/viva/sample_snapshots/five-year-life-v1
```

The output directory must be new. Preserve prior build evidence outside the
package before replacing an artifact. The builder uses the production capture,
verification, posting and SQL pipeline with bundled synthetic readings. It can
export an already complete synthetic production build with `--existing-instance`;
modified history, additional sources or incomplete preparation are rejected.
The tool prints and updates the metadata pin. The final packaged artifact must
still be restored and reopened in acceptance; successful export alone does not
prove installed delivery or real-vault import performance.

The source build records per-document duration at the complete production
capture-and-ingest boundary, cumulative elapsed time and committed event count
in each progress receipt and the final report. Resource loading, sweep, SQL
publication, financial source checks and cold replay agreement have separate
measurements. The replay check decrypts a new authenticated event snapshot and
compares the live financial fold with a fresh projection, including exact
balances, movements, holdings, instrument allocations, source observations,
component states and effect identities. Lazy query caches and resolver functions
are excluded. Any disagreement prevents readiness. Restoring still authenticates
and replays canonical history on opening; its complete measured duration, rather
than archive-copy speed, establishes the delivered sample performance.
