# tool: query_ledger
Read the ledger in totals. This is the tool that answers "how much", and for most questions one call of it is the whole answer. entity says what to read: "balances" (each real account's balance, with grade and source), "transactions" (a summary of the movements matching the filters — how many, money in, money out, net, and the same broken down by account and by month; it returns no individual rows), "holdings" (measured positions from each account's latest statement), or "aggregate" (metric "spending" grouped by group_by, metric "income" per currency, or metric "net_worth" as of a date).
net_worth is the direct answer to "what am I worth": it takes no filters, it returns net, assets and liabilities per currency and a line per account, and it is complete on its own — never assemble a net worth yourself out of balances and holdings.
income is a lifetime figure over everything ingested; it does not answer by date window yet, and it says so in its own caveats.
Counterparties are matched on an exact key, never on a name you guess. "aggregate" with metric "spending" and group_by "merchant" is how you discover which keys exist; use one of those keys in a merchant filter.
filters narrow by account, category, tag, merchant, nature, currency, or a from/to date window; every filter value must be one the vault actually holds, and an unknown value is refused with the known values named. A filter an entity does not honour is refused rather than ignored.
Every number returned comes back as a figure with an id, its grade and the documents it rests on. Amounts are exact decimal strings; nothing is converted between currencies.

# tool: list_movements
The individual movements, for a question about something in particular. Use it only when the person asked to see actual transactions — otherwise query_ledger's transactions summary answers with a fraction of the words. It requires at least one narrowing filter (account, category, merchant, tag or window) and refuses without one, and it shows at most a page of rows, stating how many matched in total and how to narrow further. Each row carries its record id, date, description, amount, currency, nature, category, tags, grade and source document, and each amount comes back as a figure you can cite.

# tool: check_completeness
How complete and how current the picture is: documents held versus posted, statements awaiting review and why, each account's latest evidenced date, and how many counterparties are still unidentified. Ask before trusting a total for anything that needs every statement present, and use the answer to say what a figure does not yet include. It is not a prerequisite for every question — a read that already carries its own coverage and caveats has told you what it does not cover.

# tool: get_provenance
Where a figure comes from. Give record_id as a movement key, an account id, or a document id; the answer names the source document, page and region, the verification grade, and — for a movement — the rung that decided its nature. Use it to answer "why do you say that?" about any figure another tool returned.

# tool: get_transparency
What the agent has done on its own and what questions were set aside. topic "agent_activity" lists every unattended action with its outcome; "calls_spent" counts the model calls the agent spent, optionally since a date; "declined_questions" lists the questions the person set aside and the stake each showed when declined. Its figures are about the agent's own behaviour and cite the ledger events that recorded it, not documents.

# tool: compute
Exact decimal arithmetic over figures this turn already produced. expression uses +, -, *, /, parentheses, integer literals and names. inputs binds each name to either the id of a figure some tool returned in this turn, or an object {"stipulated": "<the amount the person named in their question>"} for a value they supposed rather than one on record. A decimal typed in directly is refused: if a number is worth computing with, some tool emitted it and it has an id. The result is itself a figure of kind "computed", inheriting the source documents of its inputs and the weakest grade among those that are claims about money — arithmetic is exact, so a sum of corroborated figures is corroborated. It is marked "hypothetical" instead if anything the person supposed went into it, directly or through an earlier computed figure, and a hypothetical carries no grade. It refuses to add across currencies, and refuses to mix a figure about my own behaviour with one about your money. If the arithmetic would have to be rounded it refuses rather than hand back an approximation. Never do arithmetic yourself; pass it here.
